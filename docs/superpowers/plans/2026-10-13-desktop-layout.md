# Desktop layout: implementation plan

Spec (source of truth, read the cited sections): `docs/superpowers/specs/2026-10-13-desktop-layout.md`. App: `web/` (React 19, TS, Vite, plain CSS, react-router-dom 7). All paths below are relative to `web/` unless noted. Commands run in `web/`: `npm run build && npm run lint`.

## Global rules for every WP
- Mobile (<768px) must remain byte-identical in DOM and CSS output. New CSS lives only in `src/styles/desktop.css` (and appended media-query blocks in `owner.css` / `guest.css`), always inside `@media (min-width: 768px)` / `(min-width: 1200px)` / `(hover: hover)`.
- No new dependencies. No `!important`, no element selectors in desktop.css. UI copy French with "tu", no em-dashes, no emojis.
- Owner screens never render claim state (no Tag claimed/purchased, no "pris/réservé/acheté" text, aria, title).
- Match surrounding code style and comment density (short doc comments, 2-space indent, single quotes, no semicolons).
- Do not commit. Do not touch `public/favicon.svg`. Do not start dev servers. Do not edit files outside the WP's list.
- Finish with `npm run build` and `npm run lint` (in `web/`) and report results.

## Cross-cutting design decisions (deviations/clarifications of the spec)
1. Outlet context `OwnerListCtx` (exported from `src/pages/owner/OwnerList.tsx`) is:
   ```ts
   export interface OwnerListCtx {
     bp: Breakpoint
     listId: string
     order: string[]                       // wish ids, filtered order
     closePanel: () => void                // navigate to /lists/:id keeping location.search
     setTitle: (t: string) => void         // panel title
     footerEl: HTMLElement | null          // DOM node of the panel footer; children render footer via createPortal(node, footerEl)
   }
   ```
   (Spec said `setFooter(node)`; a portal avoids render loops from unstable ReactNode identities. The prev/next buttons and "Souhait i sur n" text are rendered by `OwnerListView` itself in `SidePanel headerActions`, derived from `order` and the selected wish id parsed from `location.pathname` with `/\/wishes\/([^/]+)(\/edit)?$/` where id !== 'new'; WishDetail does not render them.)
2. Selected wish id (`selectedId`) is parsed from the pathname by `OwnerListView` as above.
3. `useSaveWish` mutation returns the wish id (verified in `src/data/mutations.ts`), so after save on tablet/desktop navigate to `/lists/:id/wishes/:id` (replace).
4. `SidePanel` desktop = `<aside>`; tablet = `Sheet variant="drawer"`.

   export type Breakpoint = 'mobile' | 'tablet' | 'desktop'
   const Q_TABLET = '(min-width: 768px)'
   const Q_DESKTOP = '(min-width: 1200px)'
   const subscribe = (cb: () => void) => { /* add 'change' listener on both matchMedia lists, return remover */ }

## WP2. useHotkeys
Files: `src/lib/useHotkeys.ts` (new). Depends WP1.
Implement exactly spec 4.2 (interface `Hotkey`, `useHotkeys(bindings: Hotkey[])`). Details: bindings kept in a ref updated each render; one `window` keydown listener in `useEffect` registered only when `useBreakpoint() !== 'mobile'`. Rules: skip if `e.repeat || e.isComposing || e.defaultPrevented`; `isTyping(el)` = el matches `input, textarea, select, [contenteditable=""], [contenteditable="true"], [role="combobox"]` or `el.closest('[role="combobox"]')`; check both `e.target` and `document.activeElement`; if modifiers `(e.altKey||e.ctrlKey||e.metaKey)` pressed, only bindings with `mod` and `(e.metaKey||e.ctrlKey)` match (and no alt); bindings without `mod` require no ctrl/meta/alt; key compare: `e.key.toLowerCase() === b.key.toLowerCase()`; `enabled === false` skipped; unless `inInput`, skip when typing; while a modal is open (`document.querySelector('[role="dialog"][data-state="open"][aria-modal="true"], [data-vaul-drawer][data-state="open"]')` non-null) only bindings whose key is `Escape` run; on handled call `e.preventDefault()` then `b.handler(e)`; stop after first match.
Done: compiles, lint clean (it is unused until WP4).
